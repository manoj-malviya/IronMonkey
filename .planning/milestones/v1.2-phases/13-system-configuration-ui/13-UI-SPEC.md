# Phase 13 — UI Design Contract

> Visual and interaction contract for System Configuration UI. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (native Razor + Tailwind) |
| Preset | not applicable |
| Component library | none |
| Icon library | Heroicons (24x24 outline, stroke-width 1.5) |
| Font | System stack (no custom font; Tailwind default) |

**Basis:** Established in Phase 9 (UI Foundation & Auth). Phases 9–12 use native Razor components styled entirely with Tailwind CSS v4. No component libraries (MudBlazor, shadcn) — all UI built with utility classes and semantic HTML.

---

## Spacing Scale

Tailwind default 8-point scale. **All spacing multiples of 4px.**

| Token | Value | Usage | Tailwind Class |
|-------|-------|-------|-----------------|
| xs | 4px | Icon gaps, inline padding, tight button spacing | p-1, gap-1, space-y-1 |
| sm | 8px | Compact element spacing, small section gaps | p-2, gap-2, space-y-2 |
| md | 16px | Default element spacing, medium section padding | p-4, gap-4, space-y-4, px-6 (table cells) |
| lg | 24px | Section padding, larger gaps | p-6, space-y-6 |
| xl | 32px | Layout gaps, major dividers | space-y-8 (not used yet; reserve) |
| 2xl | 48px | Page-level breaks | space-y-12 (not used yet; reserve) |
| 3xl | 64px | Full-page sections | space-y-16 (not used yet; reserve) |

**Exceptions:**
- Table cells use consistent px-6 py-4 for visual balance (Phases 9–12 convention)
- Icon containers: w-4 h-4 (16px) for small icons, w-5 h-5 (20px) for nav/action icons
- Rounded borders: rounded-lg (8px) for buttons and cards, rounded-xl (12px) for large containers

**Source:** CONTEXT.md (Phase 13 is Claude's discretion for spacing); confirmed by reviewing Phases 10–12 Razor pages. All use Tailwind utilities only, no custom spacing tokens.

## Typography

Four size levels. Two weights.

| Role | Size | Weight | Line Height | Tailwind Class | Usage |
|------|------|--------|-------------|-----------------|-------|
| Body (copy) | 14px | 400 (regular) | 1.5 (150%) | text-sm | Form inputs, table cell content, paragraph text |
| Body (emphasis) | 14px | 600 (semibold) | 1.5 (150%) | text-sm font-semibold | Labels, small headings, badges |
| Label (form) | 12px | 600 (semibold) | 1.4 (140%) | text-xs font-semibold | Form labels, column headers (uppercase tracking-wide) |
| Label (nav) | 13px | 500 (medium) | 1.4 (140%) | text-sm | Sidebar nav links, tab buttons |
| Heading | 20px | 600 (semibold) | 1.2 (120%) | text-lg font-semibold | Subsection headings (tabs intro text, if any) |
| Display | 24px | 700 (bold) | 1.2 (120%) | text-2xl font-bold | Page heading "System Configuration" (Phase 13 only has one page) |

**Confirmed from Phases 9–12:**
- text-xs = 12px (column headers: "UPPERCASE tracking-wide")
- text-sm = 14px (body copy, labels)
- text-lg = 18px (rarely used; subsection heading)
- text-2xl = 24px (page heading in all admin pages)
- text-base = 16px (rarely used; fallback)

**Font:** No @import or custom font. Tailwind default sans-serif stack (system fonts).

**Line height:** Confirmed by inspection of UserList and TenantManagement pages. Page headings use implicit default (1.2); body uses implicit default (1.5).

**Source:** CONTEXT.md (typography is Claude's discretion). Verified against actual Razor code: UserList.razor line 14 (`text-2xl font-bold`), TenantManagement.razor column headers (`text-xs font-semibold uppercase`).

| **Destructive (delete, reject)** | #dc2626 (red-600) | Delete buttons, rejection actions, error text | text-red-600, bg-red-50, border-red-200 |
| **Destructive hover** | #b91c1c (red-700) | Delete button hover | hover:text-red-700 |

**Accent reserved for:**
- Primary action buttons (indigo-600 background, white text, hover:indigo-700)
- Active tab indicator (underline or left border)
- Active nav link (indigo-50 background, indigo-700 text, left border)
- Form focus states (indigo outline on inputs)
- Never on secondary elements (badges, status tags, etc.)

**Destructive reserved for:**
- Delete row buttons (red-600 text, hover:red-700)
- Delete confirmation modals (red text for destructive action label)
- Rejection actions (red text)
- Error banner backgrounds (red-50, red-200 border, red-700 text)

| Save changes | "Save" or "Save [Item]" | indigo-600, semibold | Inline edit save button |
| Cancel edit | "Cancel" | slate-600, regular | Inline edit cancel button (appears next to Save) |
| Delete item | "Delete" | red-600, regular | Action column, delete button |
| Reorder up | (up arrow icon) | slate-600 | Arrow button without text |
| Reorder down | (down arrow icon) | slate-600 | Arrow button without text |

**Empty States:**

| Tab | Heading | Body Copy | CTA |
|-----|---------|-----------|-----|
| Pipeline Stages | "No pipeline stages configured" | "Add your first stage to get started." | "+ Add Stage" button (blue) |

| Workflow Rules | "No workflow rules configured" | "Create rules to automate your lead pipeline." | "+ Add Rule" button (blue) |

| Scenario | Copy | Display |
|----------|------|---------|

| Validation error (e.g., duplicate name) | "A [item type] with this name already exists. Choose a different name." | Inline error message below the field (red text, 12px) |

**Success Messages:**

| Action | Copy | Duration |
|--------|------|----------|

### 3. **Inline Edit Row Pattern** (Used by all 4 tabs)

When a user clicks an existing row to edit, that row transforms:

```
<!-- Display state -->
<tr class="border-b border-slate-100 hover:bg-slate-50 cursor-pointer">
  <td class="px-6 py-4 text-sm text-slate-900">Stage Name</td>
  <td class="px-6 py-4 text-sm text-slate-600">Active</td>
  <td class="px-6 py-4 text-right space-x-2">
    <button @onclick="() => StartEdit(row.Id)" class="text-sm font-medium text-indigo-600 hover:text-indigo-700">Edit</button>
    <button @onclick="() => OpenDeleteConfirm(row.Id)" class="text-sm font-medium text-red-600 hover:text-red-700">Delete</button>
  </td>
</tr>

<!-- Edit state (same row expands or overlays) -->
<tr class="border-b border-slate-100 bg-indigo-50">
  <td colspan="3" class="px-6 py-4">
    <div class="space-y-4">
      <div>
        <label class="block text-xs font-semibold text-slate-900 uppercase tracking-wider mb-1">Stage Name</label>
        <input type="text" @bind="_editingName" class="w-full rounded-lg border border-slate-300 px-3 py-2 text-sm text-slate-900 placeholder-slate-400 focus:outline-none focus:ring-1 focus:ring-indigo-600 focus:border-indigo-600" />
      </div>
      <div class="flex gap-2 justify-end">
        <button @onclick="() => CancelEdit()" class="rounded-lg border border-slate-300 px-4 py-2 text-sm font-medium text-slate-700 hover:bg-slate-50">Cancel</button>
        <button @onclick="() => SaveEdit()" class="rounded-lg bg-indigo-600 px-4 py-2 text-sm font-semibold text-white hover:bg-indigo-700">Save</button>
      </div>
    </div>
  </td>
</tr>
```

**Inline Edit Form Styling:**
- Expanded row uses bg-indigo-50 to distinguish from normal rows
- Input fields: border-slate-300, px-3 py-2, text-sm, focus:ring-indigo-600, focus:border-indigo-600 (Tailwind defaults)
- Labels: uppercase, tracking-wider, text-xs font-semibold, slate-900
- Action buttons: Cancel (light gray border), Save (indigo-600 filled)

**Confirmed from:** Phases 9–12 use similar patterns in UserCreate and RecipeCreate (EditForm with nested inputs). Inline row editing is new to Phase 13 but follows same input styling conventions.

### 4. **Reorder Arrows** (Pipeline Stages tab only)

```
<td class="px-6 py-4">
  <div class="flex gap-1 justify-center">
    <button @onclick="() => MoveUp(stage.Id)" 
            disabled="@(stage.Order == 1)" 
            title="Move up"
            class="p-1 rounded text-slate-600 hover:bg-slate-100 disabled:text-slate-300">
      <!-- Heroicon: arrow-up -->
      <svg xmlns="http://www.w3.org/2000/svg" fill="none" viewBox="0 0 24 24" stroke-width="1.5" stroke="currentColor" class="w-4 h-4">
        <path stroke-linecap="round" stroke-linejoin="round" d="M4.5 10.5L12 3m0 0l7.5 7.5M12 3v18" />
      </svg>
    </button>
    <button @onclick="() => MoveDown(stage.Id)" 
            disabled="@(stage.Order == stageCount)" 
            title="Move down"
            class="p-1 rounded text-slate-600 hover:bg-slate-100 disabled:text-slate-300">
      <!-- Heroicon: arrow-down -->
      <svg xmlns="http://www.w3.org/2000/svg" fill="none" viewBox="0 0 24 24" stroke-width="1.5" stroke="currentColor" class="w-4 h-4">
        <path stroke-linecap="round" stroke-linejoin="round" d="M19.5 13.5L12 21m0 0l-7.5-7.5M12 21V3" />
      </svg>
    </button>
  </div>
</td>
```

**Behavior:**
- Up button disabled if Order == 1
- Down button disabled if Order == stageCount
- Click fires PUT /api/pipeline-stages/{id} with updated Order
- UI optimistically updates; revert on error

### 5. **Form Fields by Tab**

#### **Pipeline Stages Tab**

Columns: Name, Order, StageType, Actions (Edit, Delete, arrows)

**Add/Edit Form:**
- Name (text input, required, max 100 chars)
- StageType (dropdown: Entry, Active, ClosedWon, ClosedLost)
- Order (hidden; auto-assigned or reordered via arrows)

#### **Custom Fields Tab**

Columns: Name, Type, IsRequired (badge), Options, Actions (Edit, Delete)

**Add/Edit Form:**
- FieldName (text input, required, max 100 chars)
- FieldType (dropdown: Text, Number, Date, Select, Boolean)
- IsRequired (toggle/checkbox)
- Options (text input for Select/MultiSelect types only; comma-separated values)

**Conditional UI:** Options field shown only if FieldType == "Select" or "MultiSelect"

#### **Lead Routing Tab** (No table; form-only)

**Structure:** No list table. Single form with:
- Mode selector (radio buttons): "Round-Robin" or "Territory-Based"
- Conditional fields:
  - If Round-Robin: (no additional fields; just mode selection)
  - If Territory-Based: JSON textarea for territory rules
- Single "Save Configuration" button

**Form Styling:**
```
<div class="space-y-6 max-w-2xl">
  <div>
    <p class="text-sm font-semibold text-slate-900 mb-4">Lead Assignment Strategy</p>
    <div class="flex gap-6">
      <label class="flex items-center gap-2 cursor-pointer">
        <input type="radio" name="mode" value="RoundRobin" @onchange="@((ChangeEventArgs e) => HandleModeChange((string)e.Value))" class="rounded border-slate-300" />
        <span class="text-sm text-slate-700">Round-Robin</span>
      </label>
      <label class="flex items-center gap-2 cursor-pointer">
        <input type="radio" name="mode" value="Territory" @onchange="@((ChangeEventArgs e) => HandleModeChange((string)e.Value))" class="rounded border-slate-300" />
        <span class="text-sm text-slate-700">Territory-Based</span>
      </label>
    </div>
  </div>
  
  @if (_selectedMode == "Territory")
  {
    <div>
      <label class="block text-xs font-semibold text-slate-900 uppercase tracking-wider mb-2">Territory Rules (JSON)</label>
      <textarea @bind="_territoryJson" 
                placeholder="[...]" 
                class="w-full h-64 rounded-lg border border-slate-300 px-4 py-3 font-mono text-sm text-slate-900 focus:outline-none focus:ring-1 focus:ring-indigo-600 focus:border-indigo-600"></textarea>

  </div>

```

**Error Handling:**
- Network errors → "Failed to [action]. Please check your connection and try again." (red banner)
- 400 Bad Request (validation) → Inline field error or banner with specific error
- 404 Not Found → "Item no longer exists. Refreshing..." (auto-refresh page)
- 409 Conflict → "Unable to perform action. Please refresh and try again."
- 500 Server Error → "Server error. Please try again later."

## Validation Rules

### Pipeline Stages
- Name: required, max 100 chars, unique per tenant
- StageType: required, one of Entry/Active/ClosedWon/ClosedLost
- Order: auto-assigned; cannot be duplicated (enforced by backend during reorder)

### Custom Fields
- FieldName: required, max 100 chars, unique per tenant
- FieldType: required, one of Text/Number/Date/Select/Boolean
- IsRequired: optional boolean (default false)
- Options: required if FieldType is Select/MultiSelect; comma-separated string

### Routing Config
- Mode: required, one of RoundRobin/Territory
- If Territory: TerritoryMapJson must be valid JSON (enforced by backend)

### Workflow Rules
- Name: required, max 200 chars
- TriggerType: required, one of FieldChange/StatusChange/TimeElapsed
- ConditionJson: valid JSON object (enforced by backend)
- ActionType: required, one of CreateTask/SendEmail/AssignTo/...
- ActionJson: valid JSON object (enforced by backend)

**Client-side Validation:**
- Use HTML5 required attribute on required fields
- Use type="number" for numeric fields
- Optional: Custom validation on JSON fields (basic JSON.parse() check before submit)

**Server-side Validation:**
- All validation enforced on backend endpoints (CONTEXT.md lists CreateCustomFieldEndpoint uses FluentValidation)
- UI receives 400 Bad Request with error details; display in banner

## Accessibility & Mobile Responsiveness

**Tablets & Mobile (< 768px):**
- Sidebar collapses (handled by AdminLayout)
- Tab nav scrolls horizontally if needed (use flex overflow-x-auto on nav container)
- Tables scroll horizontally (wrapped in overflow-x-auto div)
- Modals remain full-screen with padding on mobile

**Keyboard Navigation:**
- Tab through all buttons, inputs, and interactive elements (native HTML)
- Enter to submit forms, activate buttons
- Escape to close modals and cancel edits

**Screen Readers:**
- Use semantic HTML (button, input, label, table)
- aria-labels on icon-only buttons (e.g., up/down arrows: title="Move up", title="Move down")
- aria-pressed or aria-checked on toggles (native checkbox handles this)
