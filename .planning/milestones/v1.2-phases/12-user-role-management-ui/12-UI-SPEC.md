## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing, form field margins |
| lg | 24px | Section padding, card spacing |
| xl | 32px | Layout gaps, major blocks |
| 2xl | 48px | Major section breaks, page-level gaps |
| 3xl | 64px | Page-level spacing (top/bottom) |

**Mapping to Tailwind utilities:**
- `gap-1` = 4px, `gap-2` = 8px, `gap-4` = 16px, `gap-6` = 24px, `gap-8` = 32px

- `m-1` through `m-8` follow same pattern
- `py-3` = 12px top+bottom, `py-4` = 16px top+bottom, `py-6` = 24px top+bottom, `py-16` = 64px top+bottom

## Component Patterns

### Pattern 1: UserList Page (USUI-01)

**URL:** `/admin/users`

**Purpose:** Display all users in current tenant with filtering, action buttons, and empty state.

**Layout:**
```
[Title: User Management] [+ Create User button]
[✓ Show Deactivated Users checkbox]

[Error banner if any]

[If empty] Empty state card with "Create your first user" button
[If has data] Data table with rows
```

**Table Structure:**
- Columns (left-aligned unless noted): Name, Email, Role, Status (centered), Created (date format MMM d, yyyy), Actions (right-aligned)
- Status column: Colored badge (green for "Active", gray for "Deactivated")
- Actions: "Edit" link + "Deactivate" button (deactivate only shown for active users)
- Row hover: `hover:bg-slate-50`
- Row borders: `border-b border-slate-100`
- Table header: `bg-slate-50 border-b border-slate-200`, text `uppercase text-xs font-semibold tracking-wide`

**Spacing:**
- Page title + Create button row: `flex items-center justify-between`, title `text-2xl font-bold text-slate-900`
- Show Deactivated toggle: `flex items-center gap-2 mt-4`
- Empty state container: `rounded-xl border border-dashed border-slate-300 bg-slate-50 py-16 text-center`
- Table container: `rounded-lg border border-slate-200 overflow-x-auto`
- Table cells: `px-6 py-4` for body, `px-6 py-3` for header

**Interaction:**
- Clicking "Edit" navigates to `/admin/users/{userId}/edit`
- Clicking "Create User" navigates to `/admin/users/create`
- Clicking "Deactivate" shows confirmation modal (see Pattern 4)
- Toggling "Show Deactivated Users" filters list client-side to include `IsDeleted=true` users

**Loading state:**
- `_isLoading` flag shows centered text "Loading users..."

**Error handling:**
- API errors display in red banner above table: "Failed to load users: {error message}"

### Pattern 2: UserCreate Page (USUI-02)

**URL:** `/admin/users/create`

**Purpose:** Form to create new user with auto-generated password display.

**Layout:**
```
[← Back to Users link]
[Title: Create User]

[Error banner if validation fails]

[Form: Name, Email, Role dropdown fields]
[Submit button: Create User]

[If successful: Password success modal/banner]
```

**Form Structure:**
- Wrapper: `max-w-3xl` (matches RecipeCreate pattern)
- Back button: `text-sm text-indigo-600 hover:text-indigo-700 mb-4`
- Page title: `text-2xl font-bold text-slate-900 mb-6`
- Error banner: `rounded-lg bg-red-50 border border-red-200 px-4 py-3 text-sm text-red-700 mb-4`
- EditForm with DataAnnotationsValidator
- Field container: `mb-4` for each field
- Label: `block text-sm font-medium text-slate-700 mb-1`
- Input: `w-full rounded-lg border border-slate-300 px-3 py-2 text-sm text-slate-900 placeholder-slate-400 focus:outline-none focus:ring-2 focus:ring-indigo-500 focus:border-transparent`
- Validation message: `mt-1 text-xs text-red-600`
- Submit button: `rounded-lg bg-indigo-600 px-6 py-2.5 text-sm font-semibold text-white shadow-sm hover:bg-indigo-500 disabled:opacity-60 disabled:cursor-not-allowed`, disabled while loading with text "Creating..."

**Form Fields:**
1. **Name** (required, text input)
   - Placeholder: "e.g. John Doe"
   - Validation: Required
   - Error: "Name is required."

2. **Email** (required, text input)
   - Placeholder: "e.g. john@example.com"
   - Validation: Required + EmailAddress format
   - Error: "Email is required." / "Email must be a valid email address."

3. **Role** (required, select dropdown)
   - Options populated from GET `/api/user-management/roles` endpoint
   - Default: Empty option "Select a role"
   - Display: `role.Name` for each option
   - Validation: Required
   - Error: "Role is required."

**Post-Success Behavior:**
- After POST succeeds with 200 OK
- Response includes `{ UserId: guid, GeneratedPassword: string }`
- Display success modal/banner with generated password:
  - Heading: "User created successfully!"
  - Subtext: "Share this password (displayed once):"
  - Password display: `<code>` block with monospace font (12px or 14px), copy button next to it
  - Copy button: "Copy" (uses JavaScript interop or native browser API to copy to clipboard)
  - After user closes (optionally on auto-dismiss): Navigate to `/admin/users` (list page)

**Loading state:**
- During form submit: button disabled with text "Creating..." + button opacity reduced

**Interaction:**
- Cannot submit form until all required fields filled and valid
- Password is displayed once — no way to retrieve it again in this UI (admin can reset on edit page)

### Pattern 3: UserEdit Page (USUI-03)

**URL:** `/admin/users/{userId:guid}/edit`

**Purpose:** Pre-populated form to edit user details and role; separate "Reset Password" button.

**Layout:**
```
[← Back to Users link]
[Title: Edit User: {User Name}]

[Error banner if validation fails]

[Form: Name, Email, Role dropdown fields]
[Reset Password button (separate)]
[Save button]

[If password reset successful: Password modal/banner]
```

**Form Structure:**
- Wrapper: `max-w-3xl` (matches UserCreate pattern)
- Back button: `text-sm text-indigo-600 hover:text-indigo-700 mb-4`
- Page title: `text-2xl font-bold text-slate-900 mb-6` with user name interpolated: "Edit User: {Name}"
- Error banner: `rounded-lg bg-red-50 border border-red-200 px-4 py-3 text-sm text-red-700 mb-4`
- EditForm with DataAnnotationsValidator (for name/email/role changes only)
- Field container: `mb-4` for each field
- Label: `block text-sm font-medium text-slate-700 mb-1`
- Input: `w-full rounded-lg border border-slate-300 px-3 py-2 text-sm text-slate-900 placeholder-slate-400 focus:outline-none focus:ring-2 focus:ring-indigo-500 focus:border-transparent`
- Validation message: `mt-1 text-xs text-red-600`
- Reset Password button: `type="button"` (not inside EditForm), `rounded-lg border border-slate-300 px-4 py-2 text-sm font-semibold text-slate-700 hover:bg-slate-50 mb-4`, disabled while resetting with text "Resetting..."
- Save button: `rounded-lg bg-indigo-600 px-6 py-2.5 text-sm font-semibold text-white shadow-sm hover:bg-indigo-500 disabled:opacity-60 disabled:cursor-not-allowed`, disabled while loading with text "Saving..."

**Form Fields (pre-populated from GET `/api/user-management/users/{id}`):**
1. **Name** (required, text input) — same as create
2. **Email** (required, text input) — same as create
3. **Role** (required, select dropdown) — same as create, but pre-selected to user's current role

**Reset Password Button Behavior:**
- Click triggers POST to `/api/user-management/users/{id}/reset-password`
- Response: `{ GeneratedPassword: string }`
- Display same success modal/banner as create (password shown once with copy button)
- Does NOT change the name/email/role form state

**Post-Save Behavior:**
- Form submit (Save button) triggers PUT to `/api/user-management/users/{id}` with `{ Name, Email, RoleId }`
- On success: Optional success banner or auto-dismiss after 2s, stay on page (no navigation)
- On error: Show error banner with message

**Loading state:**
- During form submit: button disabled + opacity reduced
- During password reset: "Resetting..." text in button, button disabled

**Interaction:**
- Password reset is independent of form submission
- User can reset password multiple times without saving form changes
- Form must be saved separately to update name/email/role

### Pattern 4: Deactivate User Confirmation Modal (USUI-04)

**Trigger:** "Deactivate" button from UserList row action

**Purpose:** Confirm user deactivation before executing DELETE request.

**Modal Structure:**
- Overlay modal with centered card (standard Tailwind pattern)
- Header: `text-lg font-semibold text-slate-900` — "Deactivate User"
- Body: `text-sm text-slate-600` — "Are you sure you want to deactivate [User Name]? They will no longer be able to access the system."
- Actions: Two buttons
  - Cancel button: `text-sm font-medium text-slate-700 hover:text-slate-800` (secondary style)
  - Deactivate button: `text-sm font-semibold bg-red-600 text-white rounded-lg px-4 py-2 hover:bg-red-700` (destructive red)

**On Deactivate Confirmed:**
- POST/DELETE to `/api/user-management/users/{id}/deactivate` (or DELETE with soft-delete semantics)
- Optimistic UI: Immediately set user row's `IsActive = false` in local state
- Update status badge to gray "Deactivated"
- Hide "Deactivate" button from row (only "Edit" link remains visible)
- Optional: Show inline toast "User deactivated" at bottom of page

**On Cancel:**
- Close modal, no changes

3. **UserEdit.razor**

   - State: `_selectedRoleId`, `_roles`, `_generatedPassword`, `_isLoading`, `_isResettingPassword`, `_errorBanner`
   - Methods: `LoadUserAsync`, `LoadRolesAsync`, `HandleSaveAsync`, `HandleResetPasswordAsync`, `CopyToClipboard`

## Implementation Guidance

### Code Patterns to Follow
- **Page structure:** `@page "/admin/..."` + `@attribute [Authorize]` + `@inject IHttpClientFactory`
- **API client:** `HttpClientFactory.CreateClient("AdminApi")` for all admin API calls
- **Form validation:** `EditForm` + `DataAnnotationsValidator` + `ValidationMessage` per field
- **Error handling:** Try/catch in async methods, set `_errorBanner` string for display, check `response.StatusCode == Unauthorized` to redirect to `/login`
- **Loading states:** `_isLoading` boolean flag, disable buttons + show "..." text
- **Styling:** Use Tailwind utility classes from Phase 9/10 established palette

### New Endpoints Required (backend)
Phase 12 planning will need to define these endpoints:
- `GET /api/user-management/users` — list all users in tenant (extract tenant_id from JWT claims)
- `GET /api/user-management/users/{id}` — get single user for edit page pre-population
- `POST /api/user-management/users` — create user with auto-generated password, return `{ UserId, GeneratedPassword }`
- `PUT /api/user-management/users/{id}` — update name/email/role
- `DELETE /api/user-management/users/{id}` — soft delete (set IsDeleted=true)
- `POST /api/user-management/users/{id}/reset-password` — generate new password, return `{ GeneratedPassword }`
- `GET /api/user-management/roles` — list available roles (already exists, may need tenant-scoping)

### JavaScript Interop (if needed)
- Copy-to-clipboard functionality for password display: Use `navigator.clipboard.writeText()` or custom JS interop
- Modal dismiss/overlay handling: Tailwind CSS + state flags (no additional JS needed for basic modal)
