## Layout & Responsive Breakpoints

### Signup Form Page (`/signup`)

**Desktop (1280px+):**
- Full viewport minimum height (min-h-screen)
- Centered form card: max-w-md, margin-auto
- Form card contains: title, error banner (if any), form fields, submit button, cross-link
- Recipe browser below form card: full-width recipe grid (2-column on desktop)
- Padding: px-4 (16px) horizontal on page level

**Tablet (768px):**
- Same layout as desktop
- Form card: max-w-md maintained
- Recipe grid: 2-column (2 recipes per row)
- Padding: px-4 (16px) horizontal

**Mobile (375px):**
- Form card: max-w-full (full width minus px-4 padding on each side = 375px - 32px = 343px)
- Recipe grid: 1-column (single recipe per row)
- Padding: px-4 (16px) horizontal
- Touch targets: form inputs and buttons min 44px height (from Phase 14 standard)

**Responsive implementation:** Tailwind utility classes (`md:`, `lg:` prefixes) per Blazor project patterns.

### Success Page (`/signup/success`)

**Desktop/Tablet/Mobile:**
- Full viewport minimum height (min-h-screen)
- Centered content block: max-w-md
- Vertical padding: py-24 (96px)
- Horizontal padding: px-4 (16px)
- Content layout: check icon (centered, 64px), heading, body text, button links below

```csharp
{
  "CompanyName": "string",
  "AdminEmail": "string",

  "Phone": "string",
  "RecipeId": "Guid? (nullable)",
  "CompanySize": "string",
```

**Response shape on success (201 Created):**
```csharp
{
  "SignupRequestId": "Guid",
```

**Response on validation error:** ValidationError (handled by framework, displayed in error banner)

**Endpoint attributes:** AllowAnonymous (public endpoint)

```csharp
[
  {
```

## Implementation Notes

### Form submission flow
1. User fills signup form fields
2. User optionally selects a recipe (or leaves blank)
3. On submit: ValidateModel → if valid → POST /auth/signup → if success (201) → navigate to /signup/success
4. If validation fails: display errors inline + error banner
5. If API error: display error banner (network error, duplicate email, etc.)

### Recipe browser UX
1. On page load: fetch GET /api/recipes (allrecipes, including blank recipe)
2. Display recipe cards in grid
3. On recipe card click: expand preview panel below, fetch GET /api/recipes/{id}
4. On recipe card click again (if already selected): collapse preview
5. On form submit: send selected recipe ID (or null if blank)

### Success page navigation
- Accessible only after successful signup (no direct navigation to /signup/success)
- Could use redirect after API success with state parameter, or Blazor routing
- Links back to home and login (D-10)

### Cross-linking
- Login.razor: Add "Don't have an account? Sign up" link below form card
- Signup.razor: Add "Already have an account? Sign in" link below form card
- Home.razor: "Start Free" button already links to /signup (Phase 14)
- Ensures user can navigate between login/signup/home freely

### Tailwind integration
- MSBuild target in IronMonkey.Web.csproj runs Tailwind CLI on build
- All utilities available in Razor class attributes
- Form inputs use standard Tailwind input styling pattern (from Login.razor)

### Routes configuration
- /signup and /signup/success must be added to PublicLayout pages (no auth required)
- Routes.razor already allows /signup (from Phase 14-03 plan)
- May need to add /signup/success to allowed public paths
