  <action>
The current Routes.razor wraps ALL routes in `AuthorizeRouteView` which redirects unauthenticated users to /login regardless of which page they're on. This breaks public access to / and /login itself.

Replace Routes.razor with a version that uses `RouteView` (no auth check) as the default renderer, removing the unauthenticated redirect from public pages. Admin pages are protected by `[Authorize]` attributes on the pages themselves (e.g., Admin/ pages), not by the router-level DefaultLayout.

New Routes.razor:

```razor
<Router AppAssembly="typeof(App).Assembly">
    <Found Context="routeData">
        <AuthorizeRouteView RouteData="routeData" DefaultLayout="typeof(Layout.MainLayout)">
            <NotAuthorized>
                @{
                    // Only redirect to login if the requested route is NOT a public page
                    var path = Nav.Uri.Replace(Nav.BaseUri, "/").TrimEnd('/');
                    if (path != "/login" && path != "/" && !string.IsNullOrEmpty(path))
                    {
                        Nav.NavigateTo("/login", forceLoad: false);
                    }
                }
            </NotAuthorized>
        </AuthorizeRouteView>
        <FocusOnNavigate RouteData="routeData" Selector="h1" />
    </Found>
    <NotFound>
        <PageTitle>Not found</PageTitle>
        <LayoutView Layout="typeof(Layout.MainLayout)">
            <div class="px-4 py-8">
                <h1 class="text-2xl font-bold text-slate-900">Page Not Found</h1>
                <p class="mt-2 text-slate-500">The page you are looking for does not exist.</p>
                <a href="/admin" class="mt-4 inline-block text-indigo-600 hover:text-indigo-500 text-sm font-medium">Return to Dashboard</a>
            </div>
        </LayoutView>
    </NotFound>
</Router>

@inject NavigationManager Nav
```

Key change: The `NotAuthorized` block now checks the current path. If the path is `/` or `/login` (or `/signup` for Phase 15), the redirect is suppressed — the page renders normally. Any other path that requires auth still redirects to /login.

Note: `path != "/"` check uses NavigationManager.Uri to get the current path. The `!string.IsNullOrEmpty(path)` guard prevents redirect on base URL edge cases.

Important: Home.razor uses `@page "/"` and has no `[Authorize]` attribute, so AuthorizeRouteView will still trigger NotAuthorized for anonymous users. The path check prevents the redirect.

Alternative approach worth knowing: Since `@layout PublicLayout` on individual pages overrides DefaultLayout, the layout issue is solved. The redirect issue requires the path check OR removing [Authorize] from nothing (since Home/Login have no [Authorize] anyway). 

Actually — re-reading Blazor docs: AuthorizeRouteView only invokes NotAuthorized when the route's page has `[Authorize]` attribute. Pages WITHOUT [Authorize] render normally for anonymous users. Since Home.razor and Login.razor have no [Authorize] attribute, the existing Routes.razor actually allows them to render anonymously.

Given this: the only change needed is ensuring public pages specify `@layout PublicLayout` to override DefaultLayout="MainLayout". The router redirect only fires for [Authorize]-protected pages.

Therefore, Routes.razor needs only a MINOR addition: add `/signup` to the NotAuthorized exclusion list for Phase 15, and the existing logic is already correct. However, to be safe and explicit about public pages, apply the path-check approach above. It is strictly better than the original.
